## 2. 设计方向

- 产品型后台界面，轻量、柔和、清晰，不做营销页。
- 大面积冷白与浅蓝紫背景，状态区域使用低饱和粉彩色。
- 主操作使用近黑色，避免大面积高饱和紫色。
- 信息层级依靠字号、字重、留白和背景色，不依赖粗描边。
- 卡片圆润但不软弱，阴影很轻；不使用玻璃拟态、渐变文字或彩色侧边条。
- 最多两层视觉海拔：应用主面板、任务卡片；避免卡片内继续嵌套卡片。

## 4. 字体

```css
font-family: Inter, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;
```

| 用途 | 字号/行高 | 字重 |
|---|---:|---:|
| 页面主标题 | 36/44px | 700 |
| 抽屉主标题 | 32/40px | 700 |
| 指标数字 | 28/34px | 700 |
| 区块/列标题 | 18/26px | 600 |
| 卡片标题 | 15/22px | 600 |
| 正文/表单内容 | 14/22px | 400 |
| 按钮/标签 | 14/20px | 600 |
| 字段标签 | 13/20px | 500 |
| 时间/辅助信息 | 12/18px | 400 |

- 数字使用 `font-variant-numeric: tabular-nums`。
- 中文正文行长控制在 38–56 个汉字，编辑器正文行高 1.65–1.75。
- 标题字距 `-0.02em`，正文不压缩字距。
- 不使用衬线、展示型字体、超细字重或全大写英文核心标签。

## 6. 应用骨架

- 桌面页面外边距 16px，主应用壳圆角 28px，最小高度 `calc(100vh - 32px)`。
- 左侧只有 72px 图标栏，不增加文字侧栏。
- 顶部居中悬浮导航高 48px，包含：项目、帖子类型、QC 要求、文案看板、飞书输出。
- 当前导航为近黑色胶囊和浅色文字；其他项仅显示文字。
- API 与飞书连接状态只读，配置来自 `.env`，界面不提供密钥输入。

### 6.1 帖子类型页面

- UI 统一称“帖子类型”，内部数据名可以继续使用 `copy_type`。
- “添加帖子类型”建立空白类型；类型编辑器提供可组合勾选的“参考案例”和“描述要求”，并保留从类型 Brief 识别入口；不展示系统预设类型。
- 参考案例按完整帖子录入标题、正文和话题，可粘贴或上传 txt/md/docx。一篇即可建立类型，同一类型最多 5 篇，不提供链接抓取。
- 描述要求用于补充标题方向、正文结构、语气、人设、场景和话题要求；下方独立设置“一定要有”和“一定不要有”。
- 编辑区左侧展示依据输入，右侧展示 AI 拆出的标题钩子、结构节拍、叙事视角、语气、人设、场景、信息密度、结尾和标签策略，所有字段可编辑。
- 单独显示“来源事实不会带入当前项目”和“避免照搬的独特表达”，确认后才形成帖子类型。
- 原帖全文与拆解画像都保留；界面明确提示原帖会进入生成 Prompt，并会执行防照搬相似度 QC。
- 用户未单独填写类型 QC 时，“一定要有/一定不要有”自动显示为默认 QC，可在 QC 页面继续修改。
- 类型卡片显示来源标签：手动、Brief、爆款参考；爆款参考类型提供查看来源与重新分析入口。
- 从项目 Brief 识别出的类型只能作为建议，仍需用户确认。

## 7. 看板与状态

```css
grid-template-columns: repeat(5, minmax(240px, 1fr));
gap: 16px;
```

固定列顺序：

1. 待 AI QC
2. AI QC 中
3. AI 修改中
4. 待人工审核
5. 已完成

业务流转：

- AI QC 通过：直接进入已完成，完成原因为“AI 自动通过”。
- 自动 QC 发起的 AI 修改：修改后返回待 AI QC，通过后可直接完成。
- 人工发起的定向 AI 修改：修改后返回待人工审核，不得自动完成。
- 待人工审核只接收异常项或用户主动召回项。
- 不设置“一轮修改/二轮修改”列，次数作为卡片元信息。
- P0 不允许跨列拖动。

列使用对应粉彩背景、20px 圆角和 12px 内边距；任务卡使用 `--surface`、20px 圆角和轻阴影。卡片至少显示 ITEM ID、用户自定义类型、标题或处理进度、状态/问题、时间。待人工审核卡片提供黑色“审核”按钮。

已完成卡片区分：

- AI 自动通过
- 人工通过
- 强制通过 · 有遗留问题

统计必须满足：总文案等于五列数量之和；AI 处理中等于 AI QC 中与 AI 修改中之和。

## 8. 按钮

- 小按钮 32px，常规按钮 40px，主要按钮 44px。
- Primary：近黑底、浅色文字。
- Secondary：浅色表面、1px 细边框。
- Warning：浅桃背景、深橙文字。
- Danger：浅红背景、深红文字。
- Text：无底色，用于查看、定位。
- 必须实现 default、hover、focus-visible、active、disabled、loading。

```css
:focus-visible {
  outline: 2px solid var(--focus);
  outline-offset: 2px;
}
```

## 9. 人工审核

- 使用宽侧抽屉或覆盖式大面板，约为视口 68%，最低宽度 960px。
- 左侧约 64% 编辑标题、正文和标签；右侧约 36% 展示 QC 结果、证据、建议和修改记录。
- 文本编辑器支持直接修改；选中文字后出现黑色胶囊“让 AI 修改”，同时提供右键入口和键盘可达入口。
- 人工定向 AI 修改完成后返回待人工审核。
- 底部顺序固定：保存修改、未通过、强制通过、正常通过。
- 正常通过为黑色主按钮；强制通过为浅桃按钮并提示必须填写遗留问题。
- 强制通过弹窗自动带入未解决问题，遗留问题不可为空，可补充放行理由。
- 用户直接编辑后仍停留在待人工审核；保存时同步运行确定性硬规则检查。

## 10. 动效

- 普通交互 150–220ms，推荐 `cubic-bezier(0.22, 1, 0.36, 1)`。
- 只动画 `transform` 与 `opacity`，不动画 `width`、`height`、`left`、`top`。
- 卡片 hover 仅 `translateY(-1px)` 和轻微阴影增强。
- 审核面板从右侧进入 220ms。
- 不使用弹跳、弹性或装饰性页面入场动画。

## 11. 响应式

- ≥1440px：五列完整展示。
- 1024–1439px：保持列宽并横向滚动，不压缩卡片。
- 768–1023px：隐藏左图标栏，顶部导航改为横向滚动标签。
- ≤767px：看板改为单列状态列表，用状态分段控件切换。
- 小屏人工审核改为全屏页面，正文与 QC 结果纵向排列。
- 字号固定，不使用 `clamp()` 或流式字号。

## 12. 可访问性与边界状态

- 正文对比度至少 4.5:1；状态同时显示文字或图标，不能只靠颜色。
- 所有图标按钮必须有 `aria-label`。
- 键盘可进入任务卡、审核按钮、定位按钮和编辑器操作区。
- 加载使用内容骨架；空状态说明下一步。
- API 失败保留卡片和编辑内容，提供单条重试。
- 截断内容提供完整查看入口。
- 强制通过的遗留问题不得为空。
- 尊重 `prefers-reduced-motion`。

## 13. 实现约束

- 建立单一 token 文件；颜色、圆角、阴影、字号与状态映射不得散落在 JSX。
- 看板列、任务卡、统计卡、状态标签、审核面板和 QC 问题项均为可复用组件。
- 不引入重量级拖拽或富文本编辑器；P0 使用可控文本输入与标签编辑。
- 不从视觉稿硬编码绝对坐标。
- 所有文案内容来自数据层。
